Intelligent Educator · architecture · 2026-10-26

Low-level design

Components and interfaces, the path of one question, the KG schema, stores and ports, the job and evaluation pipelines, and how configuration is versioned.

← High-level architecture Evidence: code doc ours unverified

TL;DR

  1. One question runs 21 steps: wrapper (settings, follow-up rewrite, source policy), the R list (dense + BM25, RRF, cross-encoder top 10), the graph list (link, route, walk, collect, hop-balanced rank to k_graph 30), fusion, packing to budget B, the gate, the answer and an optional support check.
  2. The thesis and the product share the code but not every number: B is 4,000 in the thesis and 12,000 in the app; the app caps the cross-encoder at 12 passages per hop; the thesis scores every passage.
  3. The KG has three typed concept relations. PREREQUISITE_OF is read as “A is taught before B”; the router walks it inwards to collect what a concept needs.
  4. Stores: Postgres (schemas content, learner, public), Neo4j (a rebuilt view of the frozen KG files), and read-only files (corpus, KG generation, manifests, lessons-site).
  5. Every config has a 12-character hash; every experiment has a manifest that refuses a dirty core or a changed input.

Hop-balanced rank (hop-balanced/1)

A seed concept alone has 38-456 passages, so “nearest hop first” (rule 7) gave all graph slots to hop 0 on every stored question doc. Addendum D shares the k_graph slots out per hop code:

Hops presentwant = k_graph 30Quota rule
0, 1, 2 (thesis depth 2)10 / 10 / 10ceil(slots left / hops left), best CE first, then backfill in (hop, -CE, id) order
0, 1, 2, 3 (app max_hops 3)8 / 8 / 7 / 7same rule through a private helper; trace says “depth 3, exploratory”
0 onlyup to 30 from hop 0shortage is recorded, never filled from elsewhere

The product caps each hop group at 12 cross-encoder pairs, closest by dense similarity, so one question scores at most about 4 × 12 + 10 = 58 pairs. Measured on the 8 GB Mac, warm: 21-34 s per hybrid answer at B 8,000-12,000; cold starts 70-143 s doc.

Load policy kg-load-policy/3: H and Hc load asserted edges with gate = supported, or relation = PREREQUISITE_OF, minus the quarantine; every PRE candidate was read by an Opus judge first code. The core receives only (source, target, relation, opaque edge id): no gate, review state or flags code. Hc keeps the same edges but ignores the relation mask (the mechanism ablation). Arm G uses LightRAG's own graph, not this one.
