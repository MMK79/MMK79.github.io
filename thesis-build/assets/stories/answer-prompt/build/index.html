A layered lesson on the tutor's instructions

Choosing the answer prompt

Every retrieval arm answers under the same instruction, the answer prompt. Pilot 1 showed that one sentence of it was unclear for exercises. This page shows the three candidate prompts, how one rule chose between them on practice items only, and why the choice had to be fixed before the main run.

The abstain rule, before and after If the passages do not contain the answer, reply with exactly NOT_IN_MATERIAL and nothing else. Do not reply NOT_IN_MATERIAL only because the final result is not written in a passage; an exercise asks you to derive it. If a fact that the answer needs is not in the passages, reply with exactly NOT_IN_MATERIAL and nothing else.

Builds on Query flow (what each arm sends to the model) and One scorer, set before tuning (the same "set it before tuning" logic, for scores). The pilot results are on the page.

TL;DRthe short version

In five lines

  1. In pilot 1 the retrieval arms abstained on 135 of 270 generations. No cause was split out between the prompt and retrieval.
  2. The registered prompt, P0, said to abstain when "the answer" is not in the passages. For a derivation exercise the final result is never in a passage, so the rule is unclear.
  3. Two new candidates, P1 and P2, and a selection rule were hashed before any of them ran. They ran on 18 practice (dev) items only, with no judge.
  4. P2 won: it abstained on 1/12 of cells with gold evidence, against 5/12 for P0, with valid citations on 32/33 answers.
  5. P2 is now the one prompt of the retrieval arms R, H, H-collapsed and G. It cannot change after pilot 2.
Level 0like I am five

"Only use the book"

A teacher tells a student: "Answer only from the book. If the book does not have the answer, say not in the book."

Then the homework says: "Prove this formula." The book has every fact the proof needs. But the finished proof is not printed in the book. So the student often says "not in the book", even with all the facts in front of them.

A better instruction: "Take the facts from the book. You may do the maths yourself. Say not in the book only when a fact you need is missing."

The teacher writes three versions of the instruction and tries them on practice homework, not on the real exam. A rule, written before the try, picks the winner. Then the instruction is locked for the exam.

unclear instruction→three versions→practice items, fixed rule→winner→lock it
Level 1student

What the prompt controls, and how we measured it

The answer prompt is the fixed system instruction that the answer model reads before the question and the passages. All retrieval arms share it.

To abstain is to reply with the fixed word NOT_IN_MATERIAL instead of an answer. On an answerable item, an abstention scores 0. So the abstain rule moves the result directly.

Gold evidence is the set of passages that our gold annotation accepts as the support for an item. A cell is one (item, arm) pair. A cell is gold-present when at least one accepted gold passage is in its packed context.

One real example, worked

Pilot 1, item prml:ex2.51, prompt P0

The item. Prove trigonometric identities from exp(iA). The answer is a derivation: it is not written in any passage.

What H sent. Both required gold passages were in H's context.

What happened. H abstained. Under P0 the model asked "is the answer in the passages?" and the true answer to that is no.

Under P1 and P2 the question becomes "is a needed fact missing?" Here no fact is missing, so the prompt tells the model to derive the result. 25 of the 30 pilot items are proof, derivation or numeric exercises, so this case is common.

The worked selection, step by step

The rule reads four numbers per prompt. A_present: abstention rate on gold-present cells. A_absent: abstention rate on the other cells. CV: share of answers whose citation markers all name a packed passage. D = A_absent − A_present.

  1. Eligibility: CV must be at least 0.90. P1 has 9/10 and P2 has 32/33, so both are eligible.
  2. Two eligible: the lower A_present wins if the gap is at least 0.05. P1 5/24, P2 1/12 = 2/24: the gap is 3/24 = 1/8, so P2.
  3. Margin over P0: P2 must have A_present at most P0's minus 0.10. 5/12 − 1/12 = 1/3, so P2 replaces P0.

    Level 2academic

    Tuning on an outcome proxy, in the open

    Abstention is endpoint-related: an abstention scores 0 on these answerable items. So choosing a prompt by abstention is tuning on an outcome proxy. The protocol says so, and allows it on dev only.

    What was fixed first

    Before any dev generation under P1 or P2, the candidates, the executable selector, the dev item file and the protocol were hashed in a pre-commit manifest. The runs were fixed too: the 18 gold dev items, arms R and H, one generation, the same retrieval cache and order for all three prompts, no judge, no other candidate, no second round. H-collapsed was not run: with the placeholder router it equalled H, so it would count the same cells twice.

    The dev runs were sealed: generation only, no judging, no trace. The selector stored aggregates only, and no raw dev reply was opened before the selection record was committed.

    The rule and its limits

    Eligible iff CV ≥ 0.90; between two eligible prompts, the lower A_present; under a 0.05 gap, the larger D; and the winner replaces P0 only with a margin of 0.10. The thresholds are operational choices, not uncertainty guarantees: 18 clustered items are few. Gold presence does not show that the context is sufficient, and CV checks that markers point at packed passages, not that the passage supports the sentence.

    P2's D is 0: it abstains as often with gold evidence as without. On dev, its abstention no longer follows the evidence, so the risk moves from "refuses too often" to "answers without support", which the judge and the citation proxy must catch.

    An amendment, named as one

    The change was made after pilot 1 had been seen, so it amends the registration; it does not preserve it. What it keeps: no main-set outcome informs any choice, and every choice is hashed before the data it governs. The thesis lists this under threats to internal validity: the prompt was chosen on an outcome-related quantity, but no main item had been answered and no choice used the H − H-collapsed difference.

    Pilot 1 under P0 stays as a historical comparator beside pilot 2 and the main run. It is not a clean prompt sensitivity, because the prompt, router, sample and code all changed together.

    Level 3our thesis choice

    Why one prompt is fixed before the main run

    The thesis compares arms under one prompt and one cap. If the prompt could still change, a later choice could respond to a result and favour one arm. So the prompt was chosen first, on dev, and then hashed into the configuration. Only after it were R's settings and H's router tuned. It is the same logic as the scoring page: the input is set before tuning, so no result depends on a choice made after it.

    The answer interface has no temperature control, so identical requests can return different text. That is why each confirmatory answer is generated three times and the item takes the majority label. A fixed prompt makes the instruction the same for every arm; it does not make the model deterministic.

    The claim carries a scope line for this reason: arms answer under a passage-restricted prompt, and the model answers most items without retrieval (pilot p_L 0.93).

    What we gain

    Every retrieval arm reads the same instruction, chosen by a rule that was written down before it ran and that never looked at accuracy or at H − H-collapsed. After pilot 2, nothing about the prompt may change in response to its outputs.

    Threats that stay

    An equal cap is not equal exposure: used tokens and list lengths differ between arms and are reported per item and arm.

    44 of 50 sampled (question, passage) pairs reach the cross-encoder's 512-token cap and are cut; the effect on ranks is not measured. Fusion merges two lists, and R's list can take over the context; that dominance is reported per item.

    The hop-balanced rank includes a backfill pass and a hop-first output order, so fusion and packing can still erase deeper-hop differences.

    Pilot-2 outputs and raw dev replies are sealed until the pilot closes. How each arm builds its context is on Query flow; where the ranking scores come from is on One scorer, set before tuning.
