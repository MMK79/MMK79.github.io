Evaluating RAG and GraphRAG

How do you grade an answer that a retrieval system wrote? This page explains tools that grade answers (the RAGAS library, and two small checking models called HHEM and MiniCheck), four times over: as a picture, for a student, with the research, and as the harness of our thesis. One real example runs through all of it: three questions from our pilot set, answered from the CS 156 lectures and then graded.

TL;DR

  • RAGAS is an open-source Python library (Apache-2.0) of metrics for retrieval-augmented generation. Most of its metrics ask an LLM to act as the judge; a few are plain code. This page uses version 0.4.3. In the thesis, RAGAS appears only in a small descriptive appendix; it does not decide any claim.
  • "Fully correct" is our primary score. Multiple-choice and true/false items: the answer letter must match the key (no judge). Open items: in the thesis protocol, two LLM judges from two model families must both say fully correct. This page shows the RAGAS AnswerAccuracy version of that check, which counts only with both judge ratings valid, because RAGAS silently uses one rating when the other fails.
  • HHEM (Vectara's hallucination evaluation model) and MiniCheck (Tang et al.) are small models, not LLM judges. Each reads a passage and a claim together and scores whether the passage supports the claim. HHEM gives the unsupported-claim rate inside RAGAS; MiniCheck gives the citation precision and recall of ALCE.
  • We also report gold-evidence recall and precision in the packed context and cost per correct answer (RAGAS faithfulness and FactualCorrectness only in a small post hoc appendix), and we compare systems with an exact McNemar test. Among the GraphRAG papers we read, only Edge et al. test significance at all.
  • The example shows why one number is not enough.
Level 0in one minute

Three ways to grade homework

For anyone. No technical words.

A student answers questions with an open textbook and writes the page number after each sentence. How does a teacher grade this?

The answer key

For a multiple-choice question, compare the letter with the key. No opinion is needed, so this is the safest check.

Two marking sheets

For an essay, a teacher marks it twice against a model answer, with two different sheets, each giving 0, 2 or 4 points. "Full marks" means both sheets say 4. If one sheet is lost, the school's form quietly uses the other one alone. We do not accept that.

A fact-checker with a highlighter

A third person checks each sentence against the page the student cited. A true sentence with the wrong page number still fails this check.

One answer, three checks. Each check asks a different question, so each can pass while another fails.

Takeaway: "correct", "supported by the book" and "cites the right page" are three different questions. A good evaluation asks each one separately, and decides in advance which one is the main score.
Level 1for a student

What each metric looks at

For a student who knows what RAG is: a system that retrieves passages and gives them to a language model, which writes the answer.

A RAG answer has four parts that can be checked: the question, the retrieved passages, the answer (with citation markers such as [2]), and, in a test set, a reference answer. Every metric compares two or three of these parts. The figure shows which parts each metric reads, and who decides: plain code, an LLM judge, or a small checking model.

code (deterministic)LLM judge (RAGAS prompt)small checking model (HHEM, MiniCheck)

Arrows show what each metric reads. Exact match runs on multiple-choice items, AnswerAccuracy on open items, the others on every item; only "fully correct" decides the comparison between systems.

Two words to keep apart

correctvs.supported

Correct compares the answer with the reference answer. Supported (faithful, grounded) compares the answer with the retrieved passages. An answer can be correct but unsupported (the model knew it already) or supported but wrong (the passage itself was off the point).

LLM judgevs.checking model

An LLM judge is a general language model that receives a grading prompt, so its score depends on the prompt and the model. A checking model (HHEM, MiniCheck) is a small model trained for one task: read a passage and a claim together and output the probability that the passage supports the claim. It is cheaper, runs on a CPU, and comes from a different family than any answer model.
