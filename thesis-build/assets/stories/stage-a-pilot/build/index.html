Stage A pilot: results and log

Run pilot-30-final · 769 model calls · 300 generations · answers by claude-cli, judges alibaba

Read this first

  • Pilot, 30 items, descriptive only: no confirmatory claim. Arm G (the LightRAG baseline) is not in this run. Its index is pending: the earlier build stopped at Kaggle's 12 h limit (merge stage 289 of 394), and a clean staged rebuild is running. No G answer exists yet.
  • Answers: claude-sonnet-5-5 through the subscription (list price shown, not paid). Judges: DeepSeek v4.1 flash and MiniMax M2.5 on Alibaba, hard cap USD 1.00; spent USD 0.356, including 10 test calls (judge probes and a parser diagnosis).
  • Judge parser fix: the first judging pass marked 99 of 391 judge calls MALFORMED, because a reason with LaTeX braces broke our JSON reader. The 36 affected generations were judged again with the fixed reader (same prompt, same models). The numbers here are after the fix. Before it: L 0.80, R 0.27, H 0.33, Hc 0.30.
  • Retrieval arms abstain a lot: 135 of 270 R/H/Hc generations start with NOT_IN_MATERIAL (scored wrong), plus 1 near-miss variant that is not an abstention. Closed book (L) answered all 30. No cause is attributed: the post-mortem (Stage A pilot post-mortem, section 2) shows that abstention only weakly tracks gold presence, so the share of the prompt and the share of retrieval are not separated.
  • H and Hc sent byte-identical requests on all 30 items: the router is still a placeholder that allows all three relations, so H = Hc in this run. Their differences are generation noise.
  • R filled at least 0.9 of the 4,000-token budget on 12 of 30 items (T10 fails). A larger pool does not help: the stop-packing rule limits fill, and R, H and Hc fill alike, median 3,547 tokens (post-mortem, section 5).
  • Primary stratum only (PREREQ + CROSS, 20 items; C2 and gates 3-4 use these): L 19/20, R 6/20, H 7/20, Hc 7/20; H-R b = 2, c = 1; H-Hc b = 1, c = 1. Gate 3 on 20 items: s = 0/20, 95 % upper bound 0.139, so by the letter gate 3 was not triggered (and with 20 items it cannot trigger). Gate 4: psi(H,R) 3/20, 80 % upper 0.259 <= 0.30, n stays 270.
  • Record note: this run's run-manifest.json says generator 'mock' because it re-judged only; all 300 answers come from the first pass with claude-sonnet-5-5 (correction file run-manifest.correction.json beside it).

What pilot 1 changed

Pilot 1 was an implementation failure that changed the design, not evidence about the claim. Five findings led to protocol Amendment C, and a sixth led to Amendment D. All changes were hashed before pilot 2, and none uses a difference between H and Hc.

  • The placeholder router made H and Hc send identical requests on all items. Fix: a router that reads only the question text, built as rule tables and tuned on the development items; the tuned router is s7-b/2 with k_graph 30, a three-way tie broken by the pre-stated rule.
  • Gate 3 (the manipulation check) could never trigger on 20 primary items. Fix: s is measured on all 30 pilot-2 items, and the gate is evaluated once, before any pilot-2 answer.
  • R, H and Hc under-filled the cap alike, and T10 held on only 12 of 30 items. T10 stays reported as failed; its replacement checks that R's fill is not below H's and Hc's and that R's median is at least 0.80 B.
  • The retrieval arms abstained on 135 of 270 generations. Fix: a new answer prompt, P2, chosen from three hashed candidates by a registered rule on the development items (abstention only, no judge).
  • A judge-output parser error was fixed, and the affected generations were judged again before any decision.
  • Amendment D: in pilot 1 as run, 1 of 30 graph lists held a deeper-hop passage (measured); under configuration I3 with the same seeds, 0 of 30 was projected (a projection, not an observation). Fix: the rank rule hop-balanced/1, with a backfill and the output order hop, descending cross-encoder score, id; cross-encoder scores for every graph passage (one scorer source, S1).
  • Also: L is generated three times; the 18 answerable pilot candidates that were not drawn moved to the development set; the claim got a scope sentence, because L answered 28 of 30 items correctly.
  • The result is configuration I4 (config 7cae3a31), which governs pilot 2 and the main run.

Pilot 2: approved, waits for arm G

Pilot 2 is approved, with the same USD 1.00 judge cap. It runs the same 30 items under I4 with all five arms (L, R, H and Hc three generations, G one generation), as an exposed development rerun: its estimates are descriptive, and nothing changes in response to its outputs except a pre-stated gate consequence. It starts when arm G's index exists. No pilot-2 result is shown here.
